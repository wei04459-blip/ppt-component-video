# 现行AI协作入口

新任务先读[AI视频方案协议](AI视频方案协议.md)与根目录AGENT_START.md。以下为底层兼容字段；辅助自动识别不作为成品设计。

# 原生视频场景协议

GUI和Agent共用 `component_video.export` → `semantic_scene.py` → `video/src/semantic.tsx`。只有Motion Canvas负责动画。普通plan中的plain文字、表格和独立照片自动编译；若纵横比差异太大导致普通版文字过小，明确报错，需重新布置before区域或提供scene，不允许裁掉内容和回退截图。

页面可选scene，没有时自动编译普通components。scene是纯JSON，不是脚本。每段文字、每个非空单元格通过稳定sourceRef按顺序核对原句；自动检查只证明方案到场景对应，不能证明方案对原课件转录完整。仍须读原页核对结构编号、数据关系和独立照片。

```json
{
  "width": 960,
  "height": 540,
  "groups": [
    {
      "id": "title",
      "size": [900,70],
      "before": [20,10,1],
      "after": [20,10,1],
      "index": -1,
      "nodes": [{"kind":"text","x":0,"y":0,"text":"同一份原文","fontSize":30,"fontWeight":700,"fill":"#222222","afterFill":"#005ea6","id":"title-text","sourceRef":{"component":"title","path":"text"}}]
    },
    {
      "id": "content",
      "size": [400,200],
      "before": [20,200,0.9],
      "after": [520,120,1],
      "index": 0,
      "nodes": [
        {"kind":"rect","x":0,"y":0,"w":400,"h":200,"fill":"#ffffff","afterFill":"#edf7ff","stroke":"#888888","afterStroke":"#b1cde0","lineWidth":1,"radius":0,"afterRadius":8},
        {"kind":"text","x":12,"y":12,"text":"完整原文","fontSize":20,"fontWeight":400,"fill":"#222222","afterFill":"#103758","id":"body-text","sourceRef":{"component":"content","path":"text"}}
      ]
    }
  ]
}
```

- 单位为原生内容画布像素；画布按原比例放入1080×1440上下包装。推荐960×540。每页2–40个父组。
- `size`为固定的父组局部宽高；`before/after`为 `[x,y,统一缩放]`。组内所有节点维持局部位置、字号、行分段和图片比例，父组一起抬升、穿行、回弹。两态都不能越界。
- index=-1只改变样式，before/after必须完全相同，否则报错；需要移动的组用0–39整数。少量组约.07秒错峰，组数多时总错峰封顶.42秒，4秒页面保留至少约1.85秒终态停留。
- text节点每项为已经设计好的单行；需要换行就显式列多个text节点，不在帧内重排。正文默认400，标题可700。边界与阅读性必须看真实帧。
- rect节点支持fill/afterFill、stroke/afterStroke、radius/afterRadius、lineWidth。装饰支持opacity/afterOpacity，独立出现，不能遮住正文。
- image节点只用于独立照片或标志：`x,y,w,h,imageData`，imageData为原始PNG/JPEG的base64字符串。`fit`默认`contain`，保持原图比例；显式`cover`可裁切，`cropPosition:[0.5,0.5]`指定中心。禁止stretch。编译后自动落盘到隔离assets，不引用机器绝对地址或远端URL。
- 不把整张成品、文字截图或表格截图标成image。scene不能绕过components内容核对。
- 原始课件只读；每次导出独立目录。失败不覆盖旧作品，缺字体/图片/帧直接失败，不补末帧。

预览由实际Motion Canvas帧生成，首帧和终帧与导出同场景。修改scene、components、字体、引擎或依赖后旧确认失效。`renderer_fingerprint`覆盖这些输入；缓存仅在指纹相同时复用。首次预览较慢，重复预览可直接读缓存。

每个text节点必须有独立稳定的id和sourceRef。sourceRef.component对应components中的id；path为text、title、rows/行号/列号或parts/子项号/text。拆行节点可共用一个来源，按节点顺序拼接核对。合并字段可用有序path数组，如["title","text"]。每段原文及每个非空单元格只绑定一次，交换两格文字会失败。普通方案自动生成映射，显式scene必须填写。初始与最终按内容槽缩放后的有效字号均不得低于8px。

普通方案每页可选design：accent为强调色，ink为正文色，surface为卡片浅底，line为边框色，均使用六位HEX色。默认卡片使用完整面板、统一标题条和正文留白；可在短句自然语义处显式换行，避免拆开“单位”“来源”等词。复杂护理、图表等页面仍需明确设计数据并审片，不宣称任意PPT自动产生高质量设计。

## 连接线与流程方向

视频场景也支持line节点：x、y为组内位置，points为局部坐标点列表，stroke为线色，lineWidth为宽度，可用afterStroke改变终态颜色。点和线必须留在父组范围内。例如以下折线带有向右箭头：

```json
{"kind":"line","id":"flow-to-next","x":24,"y":30,"points":[[0,8],[110,8],[102,0],[110,8],[102,16]],"stroke":"#555555","afterStroke":"#005ea6","lineWidth":2}
```

箭头属于业务流程方向，不能当装饰省去。也可将源图方向准确转录为→、↓等文字节点并绑定sourceRef。必须逐项核对起点、终点、分支和先后关系；文字对应检查不能自动证明流程关系正确。图中不同方向的线不得为方便排版而统一成同一方向。该协议描述视频节点，普通版PPTX的可编辑范围以实际导出核对为准。

## 独立简陋版节点布局

复杂页可为节点增加 `before` 对象，位置使用整页绝对坐标，终态仍使用既有父组局部坐标。例：

```json
{"kind":"text","id":"step1-body1","sourceRef":{"component":"step1","path":"text"},"text":"同一条原文","x":18,"y":216,"fontSize":20,"before":{"x":40,"y":180,"fontSize":22,"fontWeight":400,"fill":"#111111"}}
```

before支持x/y、fontSize/fontWeight、fill/stroke、opacity、radius/lineWidth；图片和矩形另支持w/h。图片before的w/h是contain槽，编译后自动居中保持素材比例。before不能替换text；文字和照片不能在任何一端隐藏。装饰矩形可设before.opacity=0，使普通端成为连续正文与独立照片，而非拆散的成品卡片。每条短句保持同一原生节点，运动期间只插值位置、字号和样式，不重新换行。不同短句可在普通端相邻组成段落，终态再落入各组。普通PPT、上方静态版和下方动画起点共用这些坐标。未填写node.before的旧方案继续使用原父组变换。
