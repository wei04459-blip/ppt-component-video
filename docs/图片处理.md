# 图片处理（legacy_compatible v1）

启动工具箱，点击“图片处理”；也可直接打开 `/images.html`。页面独立于笔记作品，不需要 AI、登录或网络。导入 JPEG/PNG → 勾选效果并调参数 → 长按预览看原图 → 导出全部 → 下载 ZIP。可取消批任务、保存/切换/删除/备份/恢复预设。清空设置只关闭八组，保留数值、列表、seed 和 I/O。

处理次序：兼容解码 → 噪点 → 翻转 → 旋转 → 放大中心裁切 → HSV → 边框 → 模糊/锐化/对比度 → 编码与信息验证。算法按交接规格的设计公式实现，未宣称还原原软件源码。稳定随机子流以源文件内容 SHA256、uint64 seed 与效果名产生；变更元数据也会改变随机结果。跨依赖版本不保证逐字节相同。

兼容模式 OFF/ON 都不保留源 EXIF/GPS/XMP/IPTC/ICC/注释/PNG 文本；ON 增加结构验证。RGBA 会直接保留 RGB 通道并丢透明度，不合白底；方向标签移除，不自动转正。CMYK 直接转换 RGB，可能改变颜色。WebP、动画、16位/浮点图、单边超过20000或超过4000万像素明确拒绝。输入不超过512MiB，浏览器单张100MB，单次HTTP请求150MB。

## 源文件只读的适配

项目要求源文件只读，因此和独立桌面规格有明确偏差：浏览器上传写入应用数据目录的隔离副本，`processed` 中间目录只能位于隔离副本旁；不会写入用户原文件夹。浏览器不能获得原绝对路径，同名同内容视为重复；不同名相同内容允许导入。每批结果位于新的 `image-tools/<session>/exports/<jobid>`，无需系统目录选择，不自动打开文件管理器；提供ZIP下载与完整实际目录。CLI也先复制到临时隔离目录，结束自动清理；manifest保留 `original_source` 和原内容SHA，临时中间路径仅作当轮阶段记录。

预览使用完整分辨率共用引擎，最后由浏览器缩放。预览串行处理，仅缓存最近一个完整结果（区别于原规格512MiB LRU），旧generation不更新显示与固定中间文件。任务启动冻结配置和输入内容指纹，每次提交前检查内容；取消在步骤/提交间协作检查，Pillow单次操作不能立即抢占。已提交结果保留；页面关闭前提醒未完成任务。导出时表单锁定，后端拒绝同会话修改。

图片页当前会话列表在刷新后不自动恢复；命名预设持久化在应用数据目录 `image-tools/presets.json`。预设不保存图片和绝对路径。损坏预设保留为只读带时间戳备份。预设seed通过HTTP字符串传输，manifest/CLI仍为精确JSON整数。

## CLI

在工具箱目录，用现有虚拟环境：

```text
.venv/bin/python -m image_dedup --version
.venv/bin/python tools/generate_image_fixtures.py work/image-fixtures
.venv/bin/python -m image_dedup run --job examples/image-job.json
.venv/bin/python -m image_dedup inspect --input work/image-output/processed_rgb.png --json
.venv/bin/python -m image_dedup validate --config config.json
.venv/bin/python -m unittest discover -s tests -v
```

Windows将 `.venv/bin/python` 换成 `.venv\Scripts\python.exe`。生成器要求输出目录不存在，防止覆盖素材。job相对路径以job文件所在目录解析，目录不递归展开；拒绝未知字段/null/错误类型/越界和未支持profile。CLI stdout为JSONL，0成功/策略跳过、1图片失败、2配置错误、130取消。Ctrl+C协作取消。manifest包含展开配置、环境、指纹、阶段、尺寸、输出哈希和计数，可用original_source及resolved_config组成新job重跑。

无新增浮动处理依赖：Pillow/NumPy使用当前工具箱环境；准确版本见 `requirements-image.lock`。本次未构建Windows EXE，未在Windows真机验收。现有Mac/Windows源码启动脚本沿用。未修改随包证据和历史发布包。
